Foundation

What Is Computer Vision?

Computer vision develops methods for machines to interpret visual information from images and videos.

Levels of Understanding

  1. Classification: one label for the whole image.
  2. Detection: objects with locations and confidence.
  3. Segmentation: one class label for every pixel.
  4. Recognition: identify a particular object.
  5. Scene understanding: context and relationships.

Key Questions

  • What objects are present?
  • Where are they located?
  • What are they doing?
  • How are they related?
  • What does the scene mean?
Why multiple stages? A 2D image is ambiguous. The same object appears differently due to lighting, scale, viewpoint, occlusion, background, and pose. Intermediate features help form reliable interpretations.
Part 1

Image Processing

Image processing changes or analyzes pixel values before semantic understanding.

Image

A 2D discrete signal where each pixel stores intensity or color information.

Video

A sequence of images called frames, with time as additional information.

Pixel

A small sample of the visual scene. In 8-bit grayscale: values 0–255.

Color Models

Model Meaning Use Key Point
RGB Red, green, blue light channels. Monitors, cameras, digital images. Additive: adding light produces white.
CMYK Cyan, magenta, yellow, black ink. Printing. Subtractive: ink absorbs light.
HSL Hue, saturation, lightness. Image editing, color filtering. Separates color type, intensity, brightness.
YCbCr Luminance and chrominance. Image and video compression. Brightness handled separately from color.

Histogram Equalization & Enhancement

Brightness

Average intensity of all pixels in a grayscale image.

B(I) = (1 / WH) Σ I(u, v)

Contrast

How widely intensity values vary around their average.

Contrast ≈ variation / average luminance

Dynamic Range

Number of distinct intensity levels used by an image.

  • High: many shades, rich detail.
  • Low: fewer shades, flatter appearance.

Histogram

Counts frequency of each intensity value. Shows statistical info but not location.

Histogram interpretation: Narrow peak = low contrast. Broad spread = strong contrast. Peaks at ends = strong contrast but possible detail loss.

Noise and Spatial Filtering

Noise Type Description Useful Filter
Gaussian Many small random intensity changes. Gaussian or averaging filter.
Salt-and-Pepper Pixels jump to extreme values 0 or 255. Median filter.
Speckle Granular multiplicative variation. Adaptive filtering.
Poisson/Shot Photon-counting variation in low-light. Variance stabilization.
Spatial filtering: Apply a kernel to local neighborhoods. Low-pass smooths, median removes impulse noise, sharpening emphasizes edges.
Part 2

Video Processing Fundamentals

Video uses temporal information: how visual content changes from frame to frame.

Video Compression

I-Frame (Keyframe)

Self-contained frame. Can be decoded without other frames.

P-Frame (Predicted)

Uses information from a previous frame.

B-Frame (Bidirectional)

Uses both past and future frames for prediction.

Optical Flow

Optical flow estimates apparent motion of pixels between consecutive frames.

flow magnitude = √(u² + v²)
Type What It Estimates Advantage
Sparse Flow Motion at informative points. Efficient, useful for tracking.
Dense Flow Motion for almost every pixel. Detailed motion field.
Motion Descriptors

HOF & MBH: Understanding Motion in Videos

Traditional motion descriptors convert video motion into numerical features for action recognition.

Simple distinction: HOF = Which way is motion going? | MBH = Where does motion change?

The Three Descriptors

HOG

Histogram of Oriented Gradients

Describes appearance and shape using local gradient orientations.

Answers: What does the object look like?

HOF

Histogram of Optical Flow

Counts motion vectors according to their directions.

Answers: Which way is the object moving?

MBH

Motion Boundary Histogram

Uses gradients of optical flow to describe motion changes.

Answers: Where does motion differ from surroundings?

Understanding HOF (Histogram of Optical Flow)

Main idea: HOF describes how pixels move in a video by counting motion directions.

How HOF Works (Step-by-Step)

1. Take consecutive frames
→
2. Compute optical flow
→
3. Group by direction
→
4. Build histogram

Example 1: Walking Right

Most body motion points rightward → strong rightward-motion bin in HOF histogram.

Takeaway: HOF captures dominant motion direction.

Example 2: Jumping Upward

Motion is mostly upward → strong upward-motion bin in HOF histogram.

Takeaway: HOF is useful when direction is the main clue.

Understanding MBH (Motion Boundary Histogram)

Main idea: MBH does not just look at motion — it looks at WHERE motion changes.

Motion Boundary Intuition

  • Uniform motion → low boundary.
  • Motion change → strong boundary.
  • Focuses on differences, not absolute motion.

Why MBH if we have HOF?

  • Camera motion makes entire scene appear to move.
  • HOF may capture background motion as well as object motion.
  • MBH suppresses uniform motion and highlights motion boundaries.
  • Useful when camera motion is present.

HOF vs MBH: When to Use Each

Aspect HOF MBH
Question Answered Which way is motion happening? Where does motion change?
Captures Motion direction Motion boundaries / differences
Good For Clear directional motion Camera/background separation
Weakness Dominated by global camera motion Less direct for direction summary
Memory Aid How things move Where motion differs
Key insight: HOF tells how pixels move; MBH tells where motion changes. MBH is more robust when background or camera motion is present.

Traditional Action Classification Pipeline

Space-Time Points
→
HOG / HOF / MBH
→
Visual Words
→
Histogram
→
SVM Classifier
  1. Find space-time interest points where motion or appearance changes.
  2. Extract HOG/HOF/MBH feature descriptors.
  3. Cluster similar descriptors into visual words.
  4. Represent video as bag-of-visual-words histogram.
  5. Use SVM to classify the action.
Part 3

Object Detection Fundamentals

Object detection finds WHAT objects are present, WHERE they are, and HOW CONFIDENT the model is.

Detection vs Classification vs Segmentation

Task Output Question Example
Classification One label for image What is in the image? "Street scene"
Detection Class + box + confidence Where is each object? "Car at (x,y) [0.92]"
Segmentation One class label per pixel Which pixels belong to which class? Pixel masks
Instance Segmentation Separate mask per object instance Which individual object is it? Car 1, car 2, car 3

Detection Output Format

For every detected object, the model returns three things:

1. Class Label

What is the object? (person, car, dog, etc.)

2. Bounding Box

Where is it? (x_min, y_min, x_max, y_max)

3. Confidence Score

How confident? P(class) = 0.94

Key difference: Detection has a variable number of outputs (one per object), unlike classification which has one output.

Why Not Just Sliding Windows?

Problem 1: Location

Where should the window be placed?

Problem 2: Scale

Objects may be tiny or very large.

Problem 3: Shape

People are tall; cars are wide.

Problem 4: Computation

Testing millions of windows is expensive.

Solution: Anchors + bounding-box regression: start from rough guesses, then learn to refine them.

Anchor Boxes

A predefined rough box that the network learns to move and resize.

What an Anchor Provides

  • Reasonable starting guess
  • Covers expected object locations
  • Reduces search space
  • Multiple anchors per location

Network Predictions

The network predicts four corrections:

  • Δx: move left/right
  • Δy: move up/down
  • Δw: change width
  • Δh: change height
Key principle: An anchor is not expected to be perfect — it is simply a reasonable starting guess.

Why Multiple Anchors?

Objects appear at different scales and aspect ratios.

Tall Anchor

Useful for pedestrians and people.

Wide Anchor

Useful for cars and buses.

Small vs Large

Objects occupy very different image areas.

Scale + Aspect Ratio

Multiple anchor types improve match probability.

Non-Maximum Suppression (NMS)

Many anchors may detect the same object. NMS removes duplicates:

  1. Keep the highest-score box.
  2. Remove boxes that overlap it too much (high IoU).
  3. Repeat with remaining boxes.
Result: NMS keeps the strongest detection and suppresses highly overlapping duplicates.

One-Stage vs Two-Stage Detection

Approach Strategy Examples
One-Stage Direct prediction from feature maps YOLO, SSD, RetinaNet
Two-Stage Propose regions first, then classify and refine Faster R-CNN, Mask R-CNN
Note: Do not memorize "one-stage = fast, two-stage = accurate" — modern systems blur that distinction.

Faster R-CNN in Four Steps

1. Extract Features
→
2. Propose Regions
→
3. Extract ROI Features
→
4. Classify & Refine
  1. Feature extraction: shared CNN backbone converts image to feature maps.
  2. Propose regions: Region Proposal Network (RPN) predicts likely object regions.
  3. Extract ROI features: each proposal converts to fixed-size feature representation.
  4. Classify + refine: predict class and improve bounding box.

Intersection over Union (IoU)

IoU = |Prediction ∩ Ground Truth| / |Prediction ∪ Ground Truth|

IoU measures overlap: 0 = no overlap, 1 = perfect overlap. Typical threshold: IoU ≥ 0.50.

Detection Evaluation Metrics

Precision

"When the model speaks, how often is it right?"

Precision = TP / (TP + FP)

Important when false positives are costly.

Recall

"Of everything I should find, how much did I find?"

Recall = TP / (TP + FN)

Important when missing objects is costly.

Average Precision (AP)

Area under the precision-recall curve.

Summarizes precision-recall trade-off for one category.

Mean AP (mAP)

Average AP across all categories.

Overall detector quality metric.

Application-dependent: Medical abnormality detection → favor high recall. Automatic checkout → favor high precision. Choose threshold based on consequences of each error.

Semantic Segmentation Foundations

Semantic segmentation assigns a class label to every pixel in an image.

One-line definition: Semantic segmentation = dense pixel-wise classification.

The Spatial Resolution Problem

Deep layers provide semantic understanding but lose spatial precision:

What Improves

  • Larger receptive field
  • More semantic abstraction
  • Better understanding of context

What Is Lost

  • Fine boundaries
  • Thin structures
  • Small objects
  • Exact spatial position
Key insight: Deep layers know WHAT is present, but less precisely WHERE it is.

Upsampling Methods

Method How It Works Strength Limitation
Nearest-Neighbour Copies closest value Fast, preserves original values Blocky boundaries, no detail recovery
Bilinear Weighted averaging of nearby values Smoother output Blurs boundaries, no semantic understanding
Transposed Convolution Learns filters for increasing resolution More flexible reconstruction Cannot reconstruct fully discarded information
Architecture Journey

From FCN to U-Net and DeepLab

Each architecture solves a specific segmentation challenge.

Architecture Main Idea Problem Addressed
FCN Keep spatial grid, produce class-score maps Converts classifier into dense predictor
Encoder-Decoder Compress, then reconstruct full-resolution mask Recovers output resolution
U-Net Combines encoder-decoder with skip connections Improves boundaries and small-object recovery
Dilated Convolution Enlarge receptive field without pooling Adds context while preserving resolution
ASPP Parallel dilation rates Captures multiple context scales
DeepLabv3+ ASPP context + boundary-refining decoder Handles context and spatial precision together

Encoder: Reduces resolution, learns semantic features. Answers "What?"

Decoder: Restores resolution, produces dense predictions. Answers "Where?"

Skip Connections and U-Net

What Skip Connections Carry

  • Edges and local texture
  • Object boundary information
  • Fine spatial layout
  • Early visual patterns

Why U-Net Works

  • Deep features = semantic meaning
  • Early features = spatial precision
  • Matching resolutions can be combined
  • Works well when boundaries matter
Core memory: U-Net = encoder-decoder with matching skip connections. Deep layers know the region is a car; skip features help determine exactly where the car boundary lies.

Dilated Convolution and ASPP

Dilated convolution inserts spaces between kernel samples, seeing wider regions while maintaining resolution.

Rate 1

Local view for fine detail.

Rate 2–6

Medium view for object-level context.

Rate 12–18

Wide view for scene-level context.

ASPP: Atrous Spatial Pyramid Pooling uses parallel branches with different dilation rates. Like asking several observers with different zoom levels to describe the same feature map.
Training

Training Semantic Segmentation Models

Segmentation requires dense annotations and careful preprocessing.

Training Data Format

Image
H × W × 3
+
Ground Truth Mask
H × W
→
One Class ID
Per Pixel

A segmentation mask stores class IDs: 0 = sky, 1 = building, 2 = road, 3 = car, etc.

Ignore labels: Ambiguous or unlabeled pixels use an ignore label (e.g., 255) excluded from loss computation.

Cross-Entropy Loss

Pixel-wise cross-entropy treats segmentation as classification repeated across the grid.

CE = −log(P(true class))

Handling Class Imbalance

Weighted Cross-Entropy

Assign larger weights to rare classes.

Caution: weights that are too large can make optimization unstable.

Focal Loss

Reduces contribution of easy pixels, focuses on difficult ones.

Useful when background pixels dominate.

Dice Loss

Useful when foreground is small. Focuses on region overlap.

Data Augmentation Rules

  • Apply same flip, crop, rotation, scale to image AND mask.
  • Color jitter and noise apply to image only.
  • DO NOT interpolate class IDs as if continuous.
  • USE nearest-neighbour interpolation for masks.
Common dataset bug: Bilinear interpolation turns class IDs (1, 2) into invalid values (1.5). Use nearest-neighbour for masks!

Training Pipeline

  1. Load image and mask.
  2. Apply aligned augmentations.
  3. Forward pass → compute logits.
  4. Compute loss over valid pixels.
  5. Backpropagate and update parameters.
  6. Validate using mIoU and Dice.
Evaluation

Metrics and Model Evaluation

High pixel accuracy does not guarantee a useful segmentation model.

Pixel Accuracy

Fraction of correctly classified pixels. Can be misleading when one class dominates.

Example: A medical image with 9,000 background pixels and 1,000 tumor pixels: a model predicting background everywhere achieves 90% accuracy but Dice and IoU = 0.

IoU: Intersection over Union

IoU = |Prediction ∩ Ground Truth| / |Prediction ∪ Ground Truth|

Ranges 0–1. Higher = better overlap.

Dice Score

Dice = 2|P ∩ G| / (|P| + |G|)

Mean IoU

Computes IoU separately for each class, then averages.

mIoU = (IoU₁ + IoU₂ + ... + IoU_C) / C
Key difference: Dice and IoU measure overlap but have different values. Do not use interchangeably.

Metric Comparison

Metric Measures Strength Weakness
Pixel Accuracy Correct pixels overall Simple to understand Hides poor rare-class performance
IoU Overlap prediction vs target Standard segmentation metric May not capture boundary quality
mIoU Average IoU across classes Prevents dominant classes from hiding rare ones Can hide variation unless per-class scores inspected
Dice Overlap with stronger emphasis on agreement Useful for small regions and medical images Not numerically equal to IoU
Debugging

Failure Analysis

Inspect predicted masks and identify the type of error.

Boundary Leak

Mask spills outside object or produces blurry edges.

Causes: aggressive downsampling, weak decoder.

Small Objects Missed

Tiny classes disappear completely.

Causes: object shrinks to few feature-map cells.

Class Confusion

Similar classes receive incorrect labels.

Causes: similar texture, weak global context.

Over-Smoothing

Model removes fine details, produces oversimplified masks.

Domain Shift

Performance drops with different conditions (rain, night, new camera).

Occlusion

Partially visible objects receive incomplete masks.

Debugging Checklist

  • Are image and mask transformations aligned?
  • Are mask class IDs correct?
  • Was nearest-neighbour interpolation used for masks?
  • Are ignored pixels handled correctly?
  • Is class imbalance severe?
  • Does validation contain diverse scenes?
  • Which class has the lowest IoU?
  • Are errors mostly boundary, scale, context, or domain-shift errors?
  • Have qualitative masks been inspected?
Engineering principle: When a mask is poor, ask: is the problem data, preprocessing, loss, metric, architecture, or application constraints?
Modern Directions

Transformers and Foundation Models

Modern methods connect dense masks with global context, prompts, and language.

Transformers

Attention allows distant regions to influence each other. Helps when local texture is ambiguous.

SegFormer

Hierarchical transformer encoder with lightweight decoder for dense prediction.

Mask Classification

Predict mask + class pairs instead of assigning classes pixel-by-pixel.

Examples: MaskFormer, Mask2Former.

SAM

Promptable segmentation from points, boxes, masks, or text cues.

Open-Vocabulary

Use language to specify targets: "segment the red car" or "find tumor-like regions."

Model Selection

Best choice depends on accuracy, latency, memory, annotation cost, robustness.

Conceptual shift: Segmentation is no longer limited to fixed class labels. It can be interactive, promptable, and language-conditioned.

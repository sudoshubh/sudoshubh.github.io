From regression to deep neural networks

linear regression · logistic regression · cost · gradient descent · partial derivatives · activation functions

Regression → a neuron

The deck starts with a toy: predict wages from number of pats, wags(pats) = w·pats + b, on three points (1→2, 2→4, 4→5). Linear regression finds the line; a neuron is the same line passed through a non-linearity.

linear: ŷ = w·x + b
logistic neuron: ŷ = σ(w₁m₁ + w₂m₂ + b), σ(z) = 1 / (1 + e⁻ᶻ)

Why sigmoid? Linear output ranges over (−∞, +∞), so it has no natural cut-off. Sigmoid squashes to (0, 1), readable as a probability, and gives a threshold: output < 0.5 → class 0, ≥ 0.5 → class 1. The deck's example classifies by length and width with inputs (2, 1), weights 0.5 and 0.2, bias 0.3.

Worked — one neuron. z = 0.5·2 + 0.2·1 + 0.3 = 1.5. σ(1.5) = 1/(1+e⁻¹·⁵) = 0.82 → class 1 (the deck's answer).

Cost function and gradient descent

The deck teaches optimisation on a deliberately silly model: a network with no inputs, NN() = b, trained to output 4. It is “a teaching abstraction” — it fits the definition of a network but exists only to explain cost and gradient descent.

cost(b) = (prediction − target)² = (b − 4)² → parabola, minimum at b = 4
slope = d cost / db = 2(b − 4)
update: b ← b − η · slope
  • Slope tells direction: slope > 0 → decrease b; slope < 0 → increase b; slope = 0 at the minimum.
  • Learning rate η: too large → overshoot and oscillate; too small → very slow. “We use a fraction of the slope to stay stable.”
  • Key sentence: gradient descent does not find the minimum by knowing the answer — it finds it by following the slope.
Worked — three steps, η = 0.1, start b = 0. slope 2(0−4) = −8 → b = 0.8. Slope 2(0.8−4) = −6.4 → b = 1.44. Slope −5.12 → b = 1.952. Each step closes 20% of the remaining gap to 4 (the update is b ← b − 0.2(b−4)).

Many examples, two parameters

With the three-point dataset the cost is the sum of squared errors, a function of two variables — a bowl-shaped surface over the (w, b) plane with one lowest point. Gradient descent starts anywhere on the bowl and moves downhill using partial derivatives: ∂C/∂w (treat b as constant — the slope along the w-slice) and ∂C/∂b (treat w as constant).

Worked — the deck's numbers. With w = 1.00, b = 1.37 the predictions are 2.37, 3.37, 5.37. Squared errors 0.37² + 0.63² + 0.37² = 0.137 + 0.397 + 0.137 = 0.67 (deck: 0.13 + 0.40 + 0.13). The exact least-squares line for these points is w ≈ 0.93, b = 1.50, with lower cost (≈ 0.64), so (1.00, 1.37) is not yet at the bottom of the bowl.

GELU in one line. ReLU switches abruptly at 0; GELU multiplies x by the probability that a standard normal variable is below x — a soft gate between 0 and 1 — so small negative inputs pass partially instead of being cut.

Word vectors

one-hot · distributional semantics · word2vec skip-gram / CBOW · negative sampling · co-occurrence · SVD · GloVe · evaluation · FastText · bias

Why not one-hot?

A one-hot vector has dimension |V| (often 500,000+) with a single 1. “Hotel” and “motel” are orthogonal: dot product 0. So there is no notion of similarity, every word is equally far from every other, and the vectors are huge and sparse. A WordNet synonym list is not the fix — lists are incomplete, similarity is graded not binary, and context changes meaning.

Distributional semantics — “You shall know a word by the company it keeps” (Firth, 1957). A word's meaning is given by the words that frequently appear near it within a fixed window. Build a dense vector (embedding, distributed representation) per word so words in similar contexts get a large dot product.

Word2vec skip-gram

1. Slide a windowCentre word c at position t, outside words o within ±m.
2. ScoreDot product of the centre vector with each outside vector.
3. SoftmaxTurn scores into P(o | c) over the vocabulary.
4. MaximiseRaise P of true context words by gradient descent on both vector sets.
P(o | c) = exp(uoᵀ vc) / Σw∈V exp(uwᵀ vc)
J(θ) = −(1/T) Σt Σ−m≤j≤m, j≠0 log P(wt+j | wt)

Why each piece of the prediction function exists (the deck steps through it):

  • Dot product = similarity; larger → more compatible.
  • Exponentiation makes everything positive (dot products can be negative; probabilities cannot) and amplifies large similarities while shrinking small ones.
  • Normalise by the sum over V (softmax) so probabilities sum to 1.

Why the objective is log, negative, averaged: log turns the product of probabilities into a sum and avoids numerical underflow; negative because optimisers minimise; averaging (÷T) so loss does not scale with corpus size.

Network view. One-hot centre word → selects a column of the embedding matrix E → centre vector h → multiplied with output matrix W (a dot product with every output word vector) → softmax → compared with the true context word. Both E (centre vectors) and W (context vectors) are updated. Why two vectors per word? Easier optimisation — each word plays two roles (centre and context); average them at the end.

The deck's pseudocode in one breath: for each (centre, context) pair h = E[center]; scores = h·W; p = softmax(scores); loss = −log p[context]; error = p; error[context] −= 1; gradients ∇W = hᵀ·error, ∇h = W·errorᵀ; update W and E[center]. “error = p minus one-hot” is the standard softmax-cross-entropy gradient.

SGD, not full batch: J depends on every window in the corpus (billions), so one full gradient is far too slow. Sample windows or mini-batches and update after each.

Variants and the training-cost trick

Model Predicts Learns

The softmax denominator is the problem. It sums over all |V| words (100k+) for every single update. Fixes: hierarchical softmax, or — standard in word2vec — negative sampling: replace the |V|-way classification with binary logistic regressions that separate a true (centre, context) pair from a few noise pairs (centre, random word).
JNS = −log σ(uoᵀ vc) − Σk=1..K log σ(−ukᵀ vc), noise uk ~ P(w) ∝ U(w)3/4

Intuition from the deck: centre “cat” in “the cat sat on the mat” — bring (cat, sat) closer, push (cat, apple) apart. Noise words come from the unigram distribution U(w) raised to a power (3/4): sampling raw U(w) would mostly pick “the” and “of”, which carry no information; the power reshapes it so rarer words are sampled more often.

Count-based vectors, SVD and GloVe

  • Window co-occurrence matrix X (window 1–10, symmetric) captures syntactic and semantic information (“word space”). A word–document matrix captures topics (“document space”) → Latent Semantic Analysis.
  • Raw count vectors grow with the vocabulary, are very high-dimensional and sparse, and make downstream models less robust. Want a dense vector of 25–1000 dims.
  • SVD: factorise X = UΣVᵀ (U, V orthonormal); keep the top k directions.
  • SVD on raw counts works badly — function words (the, he, has) dominate. Hacks (COALS): log the frequencies; cap with min(X, t), t ≈ 100; ignore function words; ramped windows (nearer words count more); Pearson correlation instead of counts with negatives set to 0.
GloVe (Pennington et al., 2014) — meaning lives in ratios of co-occurrence probabilities, not raw counts. For probe word k with ice vs steam: P(k|ice)/P(k|steam) ≫ 1 → k relates to ice; ≪ 1 → relates to steam; ≈ 1 → does not discriminate. Goal: vectors whose differences capture those ratios.
J = Σi,j f(Xij) · ( wiᵀ w̃j + bi + b̃j − log Xij )²
f(x) = (x/xmax)^α if x < xmax, else 1 (α ≈ 0.75 in the paper; the deck shows only the shape: ~0 at 0, rising, saturating)
  1. Collect a corpus; fix a context window.
  2. Count co-occurrences into X (the deck weights each count by 1/distance).
  3. Give each word a word vector wi and context vector w̃j, plus biases.
  4. Make dot product + biases predict log Xij (log stabilises counts and removes raw-frequency bias).
  5. Weight pairs with f: ignore zeros, damp rare noisy pairs, cap very frequent ones.
  6. Minimise the weighted squared error; final embedding = wi + w̃i (or wi alone).

Evaluating word vectors

Kind What Pros / cons
Intrinsic Test the embeddings on a sub-task: relatedness (cosine vs human scores — WordSim-353, SimLex-999; Spearman/Pearson), analogy (king − man + woman ≈ queen; nearest cosine), categorisation (cluster; purity/F-score), selectional preference (eat–apple vs eat–rock) Fast, interpretable; but unclear it helps a real task unless the correlation is established
Extrinsic Use as input to a real task (sentiment, NER, MT, QA); measure accuracy / F1 / BLEU Real value; slow, and you cannot tell if the embeddings or their interaction with other parts is at fault. Swap exactly one subsystem — if accuracy rises, win.

Using pre-trained embeddings: initialise from word2vec/GloVe/FastText instead of random → faster convergence, better with little data. Fixed: fewer parameters, less over-fitting, cannot adapt. Fine-tuned: task-adaptive, risks forgetting general knowledge. Concatenate pre-trained + learned: more expressive, dimension doubles. “No one-size-fits-all embedding” (Schnabel et al., 2015).

Limitations and fixes

Limitation Example Fix named in the deck
Superficial form differences dog vs dogs are separate points; unseen “runfast” has no vector (OOV) Subword models — character n-grams (FastText), character BiLSTM/CNN, morphemes (un + fortunate + ly)

FastText in four lines. Same skip-gram/CBOW training as word2vec, but a word is the sum of its character n-gram vectors (n = 3–6) plus the whole word, with boundary marks: “where” → <wh, whe, her, ere, re>. Related forms share parameters, and a never-seen word still gets a vector from its pieces. Training updates the n-gram vectors, not one atomic vector.

Language models and RNNs

language modelling · n-grams · sparsity · fixed-window neural LM · RNN LM · teacher forcing · perplexity · sequence labelling · BIO · BiRNN

What a language model is

Predict the next word: given x⁽¹⁾…x⁽ᵗ⁾, output P(x⁽ᵗ⁺¹⁾ | x⁽ᵗ⁾,…,x⁽¹⁾) over the vocabulary. Equivalently a system that assigns a probability to a piece of text, by the chain rule:

P(x⁽¹⁾,…,x⁽ᵀ⁾) = Πt=1..T P(x⁽ᵗ⁾ | x⁽ᵗ⁻¹⁾,…,x⁽¹⁾)

It underlies predictive typing, speech and handwriting recognition, spelling correction, authorship identification, MT, summarisation and dialogue. A strong LM can answer trivia (“Stanford is located in __, California”), syntax, coreference, lexical semantics, sentiment (“the movie was __”), some reasoning and arithmetic (Fibonacci) — all as next-word prediction.

n-gram language models

An n-gram is a chunk of n consecutive words. Markov assumption: the next word depends only on the preceding n−1 words. Probabilities come from counting:

P(w | prev n−1 words) = count(n-gram) / count((n−1)-gram)
Worked — the deck's 4-gram. “students opened their” occurred 1000 times; “…their books” 400; “…their exams” 100. So P(books | students opened their) = 400/1000 = 0.4; P(exams | …) = 0.1. Everything before the last three words is discarded — “proctor” was thrown away, though it might have mattered.
Problem Why Partial fix
Sparsity 1 The n-gram “students opened their w” never occurred → count 0 → probability 0 → any sentence containing it gets probability 0, even if valid Smoothing — add a small δ to every count
Sparsity 2 The context “students opened their” itself never occurred → denominator 0 → no probability at all Backoff — condition on a shorter context (“opened their”)
Storage Must store counts for every n-gram seen; grows with n and corpus size Keep n ≤ 5 in practice
Incoherence Generated text is “surprisingly grammatical but incoherent” (Reuters trigram demo) — three words of context is too little Bigger n makes sparsity and storage worse → need a different architecture
Trap: “increase n to fix incoherence” is the tempting answer. It is wrong as a standalone fix: higher n means more unseen n-grams (sparsity) and a bigger model. That tension is the motivation for neural LMs.

Neural LMs — fixed window

Bengio et al. (2000/2003): concatenate the embeddings of the last k words → hidden layer → softmax over the vocabulary. The deck builds the idea up as: a prefix is turned into one vector by a composition function (sum of embeddings, concatenation, feed-forward, CNN, RNN, Transformer); a weight matrix with one row per output word scores how compatible that prefix vector is with each word; softmax makes a distribution.

Improvements over n-gram

  • No sparsity problem (similar embeddings share statistics)
  • No need to store all observed n-grams

Remaining problems

  • Window too small, and can never be large enough
  • Enlarging the window enlarges the weight matrix W
  • No symmetry: each window position has its own weights, so the same word at position 2 vs 3 is processed by different weights — no parameter sharing, no transfer, more data needed

The need, in one line: a neural architecture that can process any-length input with the same weights at each position.

RNN language model

Core idea: apply the same weights repeatedly. Hidden state h⁽ᵗ⁾ = f(Wh h⁽ᵗ⁻¹⁾ + We e⁽ᵗ⁾ + b); output ŷ⁽ᵗ⁾ = softmax(U h⁽ᵗ⁾ + b₂).

Advantages

  • Any-length input
  • Step t can (in theory) use information from many steps back
  • Model size does not grow with context length
  • Same weights every step → symmetry

Disadvantages

  • Recurrent computation is slow (sequential)
  • In practice hard to access information from many steps back (vanishing gradients)
Worked — count the parameters (the deck's exercise). Vocabulary 5 (one-hot input), hidden 6, no biases. Wxh = 5×6 = 30; Whh = 6×6 = 36; Why = 6×5 = 30. Total 96. General form for a vanilla RNN LM: din·dh + dh² + dh·|V|.

Training an RNN LM

  1. Get a big text corpus; feed it through the RNN and compute the output distribution at every step.
  2. Loss at step t = cross-entropy between predicted distribution and the true next word (one-hot) = −log ŷtrue word.
  3. Average over all steps. In practice use one sentence (or a batch of sentences) at a time with SGD — a whole corpus is too large in memory.
  4. Teacher forcing: during training, feed the true previous word at each step, not the model's own prediction.
Worked — cross-entropy (the deck's two cases). Gold = [0,1,0,0]. Predicted [0.1, 0.6, 0.2, 0.1] → loss = −log 0.6 = 0.51. Predicted [0.4, 0.3, 0.05, 0.25] → −log 0.05 = 2.99. A confident wrong answer is punished hard. Why log: it turns products into sums, penalises confident mistakes, gives stable gradients and pairs naturally with softmax.

Generation (autoregressive): sample a word from the output distribution, feed it back as the next input, repeat. At test time there is no teacher — the model consumes its own output.

Evaluating an LM — perplexity

perplexity = ( Πt 1 / P(x⁽ᵗ⁺¹⁾ | x⁽ᵗ⁾…x⁽¹⁾) )1/T = exp( J(θ) ) — the exponential of the average cross-entropy; lower is better

Interpretation from the deck: perplexity 1.44 ≈ “on average the model is choosing between about 1.44 equally likely words”; 4.07 ≈ almost guessing among 4.

Worked. Average cross-entropy 0.3646 nats → perplexity = e0.3646 ≈ 1.44. Doubling the number of equally likely choices adds log 2 to the loss.

Named entities and BIO tagging

A named entity is anything referred to by a proper name: PER (Marie Curie), LOC (New York City), ORG (Stanford University), GPE (Boulder, Colorado); extended to dates, times, prices. NER = find the spans and tag the type. It is harder than POS tagging because of segmentation (POS has one tag per word; NER must find the span boundaries) and type ambiguity. BIO turns it into one label per token:

[PER Jane Villanueva] of [ORG United], … → B-PER I-PER O B-ORG …
B = begins a span · I = inside a span · O = outside · tags = 2n + 1 for n entity types

LSTM, GRU, seq2seq and attention

vanishing gradients · LSTM · GRU · machine translation · encoder-decoder · bottleneck · attention · limits of recurrence

Why RNNs forget — vanishing gradients

Backpropagating through many time steps multiplies the gradient by the recurrent Jacobian over and over. If its factors are < 1 the signal from distant steps shrinks to nothing. Consequences: early layers/steps learn very slowly, training deep or long networks becomes difficult, and the model cannot connect distant words. Remedies named in the deck: ReLU, sensible initialisation, residual / direct pass-through connections, and LSTM/GRU for sequences. (If factors are > 1 you get exploding gradients, handled by clipping.)

LSTM

A separate memory cell c⁽ᵗ⁾ runs along the top; gates (sigmoid outputs in [0,1]) decide what to erase, write and expose. (Equations were images in the deck; these are the standard forms.)

forget gate f = σ(Wf[h⁽ᵗ⁻¹⁾; x⁽ᵗ⁾] + bf) — what to keep of the old cell
input gate i = σ(Wi[h⁽ᵗ⁻¹⁾; x⁽ᵗ⁾] + bi) — what new info to write
output gate o = σ(Wo[h⁽ᵗ⁻¹⁾; x⁽ᵗ⁾] + bo) — what to expose
candidate c̃ = tanh(Wc[h⁽ᵗ⁻¹⁾; x⁽ᵗ⁾] + bc)
c⁽ᵗ⁾ = f ⊙ c⁽ᵗ⁻¹⁾ + i ⊙ c̃    h⁽ᵗ⁾ = o ⊙ tanh(c⁽ᵗ⁾)
How LSTM helps with vanishing gradients (the deck's argument): if the forget gate says “remember everything” (f ≈ 1), the cell state barely changes and information survives many steps. A plain RNN has no memory control — it must learn weights that happen to preserve information, which is very hard. Gates protect information; they do not guarantee it.

GRU

A lighter recurrent unit: no separate cell, two gates, “memory” is the hidden state itself.

reset rt = σ(Wrxt + Urht−1 + br) — how much past to forget
candidate h̃t = tanh(Whxt + Uh(rt ⊙ ht−1) + bh)
ht = (1 − zt) ⊙ ht−1 + zt ⊙ h̃t

Machine translation and seq2seq

MT: translate source sentence x into target y. Sequence-to-sequence: an encoder RNN reads the source and produces an encoding (its final hidden state); a decoder RNN is a language model that generates the target, initialised from that encoding. At test time the decoder's output at each step is fed as the next step's input, starting from <START> and ending at <END>.

NMT is a conditional language model. Language model: the decoder predicts the next target word. Conditional: the prediction is also conditioned on the whole source sentence: P(yt | y1…yt−1, x). Trained end-to-end on a big parallel corpus. Multi-layer: the hidden states of layer i feed layer i+1.

The encoder-decoder idea is general — seq2seq is used for summarisation (long → short), dialogue (previous utterances → next), parsing (text → parse as a sequence) and code generation (language → Python).

The bottleneck. A long source sentence is squeezed into one fixed-size vector from which the decoder must reconstruct another long sentence — information is lost, especially for long inputs. The decoder only ever sees the final encoder state.

Attention — the fix

On each decoder step, look back at all encoder hidden states and take a weighted sum, where the weights say how relevant each source position is right now. Each decoder state therefore sees a different, dynamic context — a function of all encoder states.

  1. Score: ei = st · hi (dot-product attention) for every encoder state hi, with st the decoder state.
  2. Normalise: α = softmax(e).
  3. Context: ct = Σi αi hi.
  4. Use: concatenate/feed ct with st to predict the next word.
Worked — the deck's problem. Encoder states h₁=[2,0], h₂=[−1,2], h₃=[1,−1], h₄=[0,1]; decoder state s=[1,−2].
Scores s·h: [2, −5, 3, −2].
softmax: e² = 7.389, e⁻⁵ = 0.0067, e³ = 20.086, e⁻² = 0.135; sum = 27.617 → α = [0.2676, 0.0002, 0.7273, 0.0049].
Context c = Σ αi hi ≈ [0.2676·2 − 0.0002 + 0.7273, 0.0005 − 0.7273 + 0.0049] = [1.262, −0.722].
Sanity check: the answer sits close to h₃ = [1, −1] because h₃ has by far the largest score.

What attention buys

  • Fixes the bottleneck — decoder accesses all source states
  • Soft alignment for free (heatmaps of α show source–target word links)
  • A direct path to distant states → helps vanishing gradients
  • Used in MT and in sentence summarisation

Issues that remain with recurrence

Coreference resolution

mention detection · anaphora · cataphora · mention-pair · mention-ranking · features · neural · end-to-end spans · clustering · B-cubed

The task

Coreference resolution = identify all mentions that refer to the same real-world entity. It is “really difficult” — pronouns, nominal phrases and names all have to be linked, and the right answer often needs world knowledge. It matters wherever downstream systems need to know who “he”, “it” or “the company” is: summarisation, QA, MT, dialogue, information extraction.

1. Mention detectionFind every span that could refer to an entity: pronouns, named entities, noun phrases.
2. ClusteringGroup mentions that refer to the same entity.

Mention detection

  • Pronouns — via a POS tagger; named entities — via NER; noun phrases — via a constituency parser.
  • It is “not so simple”: many detected spans are not referential — “it” in “It is sunny”, “every student”, “no student”, and quantified or idiomatic phrases. These are bad mentions.
  • Handling them: train a classifier to filter, or — the modern answer — treat every span as a candidate mention and let the coreference model learn to link only the good ones (a mention with no antecedent is simply a singleton).

Anaphora, cataphora, coreference

Term Meaning Example
Anaphora An expression refers backward to something earlier in the text — most English pronouns “John arrived late because he missed the bus.” “I bought a laptop. It is fast.”
Cataphora An expression refers forward to something still to come — rarer, common in literary style “Before she arrived, Anna phoned.” “If you need one, there's a pen on the table.”
Coreference Two or more mentions refer to the same real-world entity “Barack Obama … the president … he”
Anaphora ≠ coreference. Coreference is a relation between mentions that denote one entity (it can link two names with no pronoun). Anaphora is a relation where interpreting an expression depends on another. They overlap heavily but neither contains the other: “Every student finished their exam” is anaphoric but “their” does not corefer with a single entity.

Three families of models

1 · Mention-pair

Train a binary classifier on every pair of mentions: p(mᵢ, mⱼ) = “are they coreferent?”. Training labels: pairs inside the same gold cluster are positives; others negatives. At test time:

  1. Score every pair (the deck: (I, my) 0.98, (Nader, he) 0.95, (I, he) 0.05, (I, Nader) 0.02).
  2. Pick a threshold (typically 0.5) — link pairs above it.
  3. Take the transitive closure: if A–B and B–C are linked, then A–C — this turns pairwise edges into clusters: {I, my}, {Nader, he}, {she}.
Why mention-pair breaks (a favourite “flaw” question). Pairwise decisions are independent but the clustering step is not. One wrong high link merges two clusters: if (my, she) is wrongly predicted coreferent, closure gives I = my = she, “totally wrong”. Conversely one missed link fragments a true cluster. The deck's names for the symptoms: “chain explosions” and “broken clusters”. A second weakness: many mentions have no antecedent (the first mention of an entity), yet the pair model is forced to compare them with everything before. This is why mention-ranking and neural span models were developed.

2 · Mention-ranking

For each mention, pick one best antecedent among all previous mentions (plus a dummy “none” option for a first mention). Train it with a softmax over candidate antecedents; the objective sums the probability of any correct antecedent (so there is no need to choose which correct one). At test time: for each mention, take the highest-scoring candidate — “my chooses I, he chooses Nader” — and the clusters appear automatically, with no closure explosion.

How the scores are computed — three generations:

Generation Scoring
Non-neural Hand-built features of the (mention, antecedent) pair — gender_match, number_match, animacy_match, exact_string_match, head_match, is_pronoun, sentence_distance, mention_distance, same_NE_type — into a classifier. For (“he”, “Nader”): gender 1, number 1, animacy 1, exact-string 0, same-NE 1.
Neural Embeddings of the mention words, of its head word (found with a dependency/constituency parser — in “the fluffy cat stuck in the tree” the head is “cat”), POS tag, plus the same distance/other features, through a feed-forward network.
End-to-end (Lee et al., 2017) Consider all spans as mention candidates and learn mention detection and linking jointly; no parser, no hand-built features.

End-to-end span model — what to be able to describe

  1. Embed every word (word + character embeddings); run a bidirectional LSTM over the document → a contextual vector x* per word.
  2. Every span i from START(i) to END(i) is a candidate (the deck's “the postal service”). Build its representation:
    gi = [ x*START(i), x*END(i), x̂i, φ(i) ]
  3. Why each term: the BiLSTM states at the span's start and end carry the context to the left and right of the span; x̂i is an attention-based representation of the span itself; φ(i) carries extra features not in the text (e.g. span width).
  4. The span's “head” is not chosen by a parser — the model learns it, by attention over the words in the span.
  5. Score each span as a mention (mention score) and each pair of spans as antecedent link (pairwise score); sum them. Prune: keep only the top-scoring spans (spans are O(n²)), and limit candidate antecedents per span.

3 · Clustering-based

Start with every mention in its own cluster. Score a candidate merge of two clusters, s(MERGE[c₁,c₂]); merge the best-scoring pair; repeat until no merge score is positive — standard agglomerative clustering. To score a merge: form every cross mention pair (one from each cluster), turn each pair into a vector (as in the mention-pair hidden layer), pool them (max/average) into one cluster-pair vector, score it with a learned weight vector.

Worked — the deck's Google example. Mentions: Google, Google Plus, the company, the product. Scores: (Google, the company) = 5 → merge. (Google Plus, the product) = 4 → merge. (Google, Google Plus) = −3 → do not merge. Result: {Google, the company}, {Google Plus, the product}.

Why clustering is easier than isolated pair linking: a pair decision (“Google” vs “Google Plus”) is ambiguous alone, but a cluster decision sees many signals at once — both clusters contain companies/products, several cross pairs look compatible, context matches better. More robust.

Evaluation — B-cubed

B-cubed scores every mention individually by comparing its system cluster with its gold cluster, then averages. It penalises both over-merging (low precision) and under-merging (low recall).

for mention m: P(m) = |sys(m) ∩ gold(m)| / |sys(m)|    R(m) = |sys(m) ∩ gold(m)| / |gold(m)|
B³ precision = mean of P(m) over all mentions; B³ recall = mean of R(m); F1 as usual
Worked — the deck's 9-mention example. System: S1 = {A B C D E}, S2 = {F G H I}. Gold: G1 = {A B C D F G}, G2 = {E H I}.
A, B, C, D: sys size 5, gold size 6, overlap 4 → P = 4/5, R = 4/6.
E: sys S1 (5), gold G2 (3), overlap {E} = 1 → P = 1/5, R = 1/3.
F, G: sys S2 (4), gold G1 (6), overlap {F,G} = 2 → P = 2/4, R = 2/6.
H, I: sys S2 (4), gold G2 (3), overlap {H,I} = 2 → P = 2/4, R = 2/3.
Precision = (4·0.8 + 0.2 + 2·0.5 + 2·0.5) / 9 = 5.4/9 = 0.60.
Recall = (4·⅔ + ⅓ + 2·⅓ + 2·⅔) / 9 = 5/9 ≈ 0.556. F1 ≈ 0.577.

Question answering

What QA is and where it came from

One of the oldest NLP tasks (punched-card systems in the early 1960s; Simmons, Klein and McConlogue 1964, dependency logic). TREC (the Text Retrieval Conference, started 1992 — the deck dates its QA track to 1992, though the dedicated QA track is usually dated 1999) set the standard for evaluating QA with factoid and complex questions; IBM Watson won Jeopardy! on 16 Feb 2011 — handling wordplay categories like “Rhyme Time” and “Before and After”, i.e. retrieval, inference and language understanding together. Consumer systems: Siri (spoken QA), Google Now; Wolfram Alpha is a computational knowledge engine over structured data, not a classic NLP system.

Factoid questions

A short fact: “Who wrote …?”, “How many calories …?”, “Where is Apple based?”. What commercial systems mostly handle.

Complex / narrative

Need synthesis: “In children with acute febrile illness, what is the efficacy of acetaminophen in reducing fever?” “What do scholars think about Jefferson's position on pirates?”

Paradigm Idea Resource
IR-based Retrieve relevant passages from a large text collection, then extract the answer Search engine / document collection
Knowledge-based Map the question to a query over structured data Knowledge graphs — Wikidata, DBpedia, Freebase; relation databases
Hybrid Combine both Watson-style

Many simple factoid questions are already answered by web-search snippets; complex or reasoning-based questions need deeper models.

Question processing — what to extract

  • Answer type detection — the entity type the answer must have (PERSON, CITY, NUMERIC, LENGTH…). Eliminates implausible candidates.
  • Query formulation — choose keywords for the IR system.
  • Question type — definition? maths? list?
  • Focus detection — the words in the question that the answer replaces.
  • Relation extraction — relations between entities in the question.

Query formulation (Moldovan et al., 1999)

Keywords are chosen in priority order: non-stop words in quotations → NNP words in recognised named entities → complex nominals with adjectival modifiers → other complex nominals → nouns with modifiers → other nouns → verbs → adverbs → the question-focus word → everything else. For “Who coined the term ‘cyberspace’ in his novel ‘Neuromancer’?” the priorities come out as cyberspace/1, Neuromancer/1, term/4, novel/4, coined/7.

Passage retrieval and ranking

  1. IR engine retrieves documents using the query terms.
  2. Segment documents into passage-sized units (≈ paragraphs).
  3. Rerank passages, using the answer type — features such as: number of named entities of the right type in the passage; number of query words; number of question n-grams in the passage; proximity of query keywords; longest sequence of question words; rank of the source document.

Answer extraction and ranking

Run a named-entity tagger for the expected type over the passages (full NER, regex, or both) and return strings of the right type: “Who is the prime minister of India?” (PERSON) → “Manmohan Singh”; “How tall is Mt. Everest?” (LENGTH) → “29035 feet”. With several candidates (Queen Victoria's second son: the passage mentions Czar Alexander II, Marie Alexandrovna and Alfred) rank with features: answer-type match; pattern match; number of question keywords in the candidate; keyword distance; novelty (a candidate word not in the query); apposition to question terms; punctuation immediately after the candidate; longest sequence of question terms.

Evaluation

  • Accuracy — does the answer match the gold answer?
  • Mean Reciprocal Rank (MRR) — for each query the system returns a ranked list of M candidates; score = 1/rank of the first correct answer (0 if none); average over N queries.
Worked. Three queries: first correct answer at rank 1, at rank 3, and not in the list. MRR = (1 + ⅓ + 0)/3 = 0.444. Note MRR rewards getting the right answer early; accuracy only asks whether the top answer is right.

Knowledge-based and mixed signals

  • Relation databases hold answers, e.g. born-in(“Emma Goldman”, “June 27 1869”), author-of(…), drawn from Wikipedia infoboxes, DBpedia, Freebase. The question is parsed into relations: “Whose granddaughter starred in E.T.?” → acted-in(?x, “E.T.”) ∧ granddaughter-of(?x, ?y).
  • Temporal reasoning: “In 1594 he took a job as a tax collector in Andalusia” — Thoreau (born 1817) is a bad answer, Cervantes (alive in 1594) is possible.
  • Geospatial knowledge: containment, directionality, borders — Beijing is a good answer for “Asian city”; California is “southwest of Montana” (geonames.org).

Dense retrieval — a bi-encoder

Sparse (keyword) retrieval misses paraphrases. A dense retriever encodes the question with one encoder and each passage with another (the deck draws LSTMs, taking the last hidden state; modern systems use Transformers) into vectors in the same space; relevance = dot product / similarity. Passages can be pre-encoded and indexed, so search is fast.

  • Training data: question–passage pairs where the passage contains the answer (positives); negatives chosen from retrieved but irrelevant passages.
  • Objective: contrastive — pull the question close to its positive passage, push it from negatives. Simplest form: one positive and one negative with a contrastive loss; better negatives (relevance-guided supervision, in-batch and hard negatives) give better retrievers.

Sentiment analysis

opinion mining · holder / target / type · lexicons · challenges · granularity · ABSA · CNN / RNN / attention · TD-LSTM · AT-LSTM · ASTE

Why it matters

“What do others think?” has always mattered (which car, which school, whom to vote for). Reviews are hard to use directly: they are scattered, one site's reviewers may share a bias, and some are fake or spam (the YellowPages moving-company example: few reviews per reviewer, dates clustered, all five-star, suspiciously many positive mentions). The same field goes by many names — sentiment analysis, opinion mining, review mining, appraisal extraction, subjectivity analysis.

  • Business intelligence: Apple wants to know what customers like, dislike and complain about, and which features to add; competitors want its weaknesses.
  • Public opinion: Twitter sentiment tracks consumer-confidence polls (O'Connor et al. 2010). Bollen et al. (2011): the “calm” mood on Twitter — not “happy” — predicted the Dow Jones with a lag of about 3 days, because markets depend on confidence and lack of panic, and decisions take time to reach prices.

What sentiment analysis is

Subjectivity = linguistic expression of somebody's private states — opinions, emotions, beliefs that cannot be objectively verified. Sentiment analysis = detection of attitudes, where an attitude is an “enduring, affectively coloured belief, disposition towards objects or persons” — enduring (long-lasting), affectively coloured (influenced by emotion), disposition (tendency to like/dislike).

1 · Holder

Who expresses it. “I love this phone” → I. “Customers hate the service” → customers.

2 · Target (aspect)

What it is about. “I love this phone” → phone. “Battery is bad” → battery. This is the root of aspect-based sentiment.

3 · Type of attitude

Detailed: love, hate, like, desire, value. Common in ML: polarity — positive / negative / neutral (sometimes with strength).

4 · Text

Where it is written — a sentence (“Camera is good”) or a whole document (an Amazon review).

Task difficulty: simplest = positive vs negative; next = rate 1–5; advanced = detect target, source, or complex attitude types. Classic benchmark: Pang, Lee & Vaithyanathan (2002) “Thumbs up?” — polarity of IMDB movie reviews (Polarity Data 2.0).

Granularity and aspect-based sentiment (ABSA)

Coarse-grained: document- or sentence-level polarity. Fine-grained: phrase- or aspect-level. “Its battery is awesome but camera is very poor” — one sentence-level label cannot be right; the correct output is positive about the battery, negative about the camera. For product reviews the useful summary is per-aspect scores (e.g. Zoom 4.5, Picture quality 5.0, Battery 1.5), not a single 3.5.

Tasks inside ABSA

  1. Aspect term extraction: given a sentence, return the aspect terms — “I liked the service and the staff, but not the food” → service, staff, food. “Awesome form factor and great battery life” → form factor, battery life.
  2. Aspect sentiment classification: polarity per aspect — positive, negative, neutral, or conflict.
  3. Complications: an implicit aspect — “very expensive for what you get” is about price but the word “price” is absent; a general sentence with no aspect at all (“I enjoy having Apple products”).
  4. Aspect Sentiment Triplet Extraction (ASTE): extract (aspect term, opinion term, polarity) — “The pizza is delicious, but the service is terrible” → (pizza, delicious, positive), (service, terrible, negative). Work cited: Peng et al. AAAI 2020; Xu et al. EMNLP 2020; Chen et al. AAAI 2021.
  5. Quad prediction (compound ABSA): four elements — aspect term, opinion term, sentiment polarity, aspect category (e.g. FOOD, SERVICE); generative formulations (Zhang et al. ACL 2021) predict them jointly. Single-element tasks predict one; compound tasks predict several with their relations.

Modelling — from engineered features to neural

Traditional MLHand-built features — n-grams, presence of cue words, lexicon scores — into SVM / decision tree.
Embeddings + MLPAverage or pool word vectors, feed a feed-forward net.
CNN / LSTMLearn the features; no feature engineering.

CNN for sentiment

  1. Embed each word. Slide a filter over consecutive n-grams (e.g. bigrams: “the movie”, “movie is”, “is very”, “very good”) — a simple linear layer applied at each window with the same weights (local connectivity + weight sharing).
  2. Problem: sentence length varies, but the final feed-forward layer needs a fixed-length vector. Max-pool over time for every filter: keep the strongest response — ideally the “very good” window, which gets the weight.
  3. Feed the pooled vector to the output layer → label.

RNN / LSTM for sentiment

Read the sentence left to right (or bidirectionally) and classify from the final / pooled hidden state. Ordering and negation are handled naturally by the recurrence, which an n-gram CNN sees only within its window.

For aspect sentiment, a plain LSTM models the sentence without considering the target, so it cannot distinguish battery from camera in “Its battery is awesome but camera is poor.”

F1 · Neural-net foundations

Why can you not make a network more powerful by just stacking linear layers?slide

W₂(W₁x) = (W₂W₁)x — a single linear map. Extra layers add compute but no expressive power. Non-linearities “bend” space so the network can approximate complex functions.

ReLU's gradient is 0 for x < 0. What problem does that create and what are two remedies?slide

“Dead neurons” — a unit stuck in the negative region receives no gradient and stops learning. Remedies: Leaky ReLU / Parametric ReLU (small slope for negatives), or smooth gates such as Swish / GELU.

Why does the deck call a network with no inputs, NN() = b, “a teaching abstraction”?slide

It meets the definition of a network but is useless as a model of data. It exists only to explain cost functions and gradient descent in one dimension, where the cost (b−4)² is a visible parabola.

Your loss oscillates wildly and never settles. What does that suggest and what do you change?practice

The learning rate is too large — updates overshoot the minimum on alternating sides. Reduce η. (Too small gives the opposite symptom: very slow, steady progress.)

F2 · Word vectors

A search for “Seattle motel” should match “Seattle hotel”. Why do one-hot vectors fail, and why does WordNet not rescue you?slide

One-hot hotel and motel are orthogonal (dot product 0) — no notion of similarity. WordNet synonym lists are incomplete, similarity is graded not binary, and context changes meaning. Instead learn similarity into the vectors themselves from context.

Why does word2vec keep two vectors per word?slide

Easier optimisation: a word plays two roles — centre and context — and using one vector for both makes the objective awkward (a word's own dot product with itself appears). Average the two at the end.

In the skip-gram probability, why exponentiate the dot product before normalising?slide

Dot products can be negative but probabilities must be positive; exp guarantees positivity and also magnifies large similarities while shrinking small ones. Then divide by the sum over the vocabulary so it is a distribution.

What is the computational problem with the softmax in word2vec and how does negative sampling solve it?slide

The denominator sums over every vocabulary word (100k+) at each update. Negative sampling replaces it with K+1 binary logistic regressions: raise the score of the true (centre, context) pair, lower it for K randomly drawn noise words. Cost per update becomes O(K) not O(|V|).

Why are negative samples drawn from U(w)^¾ rather than from the plain unigram distribution U(w)?slide

Plain U(w) would mostly return “the”, “of” — frequent words that are in almost every context, so they teach nothing. Raising to a power < 1 flattens the distribution so rarer, more informative words are sampled more often.

Why does running SVD directly on a raw co-occurrence matrix give poor vectors, and what hacks help?slide

Function words (the, he, has) are so frequent that they dominate the structure. Fixes: take logs, cap counts (min(X, ~100)), ignore function words, ramp the window so closer words count more, or use Pearson correlations with negatives clipped to 0.

Compare word2vec and GloVe in two sentences.practice

word2vec is predictive: it slides a window and updates vectors by SGD so that real context words get high probability. GloVe is count-based: it builds the global co-occurrence matrix once and fits w_iᵀw̃_j + b_i + b̃_j to log X_ij with a weighting function f that damps rare and very frequent pairs. Both end up encoding co-occurrence structure.

Embeddings score well on an analogy test but your sentiment classifier does not improve. Is that a contradiction?practice

No. Intrinsic evaluation (analogy) tests a proxy; the deck stresses it is “not clear if really helpful unless correlation to the real task is established”. Extrinsic evaluation on the task is what counts. Note too that embeddings place “good” and “bad” close (they share contexts), which hurts sentiment.

How does FastText handle a word it has never seen?slide

It represents a word as the sum of its character n-gram vectors (with < > boundary marks, n = 3–6) plus the word itself, so an unseen word still has known n-grams and therefore a vector. It also shares parameters across “dog / dogs / doggy”.

“man : computer programmer :: woman : homemaker.” What went wrong and what are the debiasing steps?slide

Embeddings learn from real text, which contains social bias; the model reproduces it. Bolukbasi et al.: identify bias-defining word pairs, compute the bias direction, neutralise words that should be neutral. Alternatives: balanced/filtered corpora. Perfect debiasing remains hard.

“whale” sits near “fish” in embedding space. Why, and what does it show about embeddings?slide

They co-occur in similar contexts (ocean). Embeddings capture statistical patterns in text, not factual knowledge, so they can be “conceptually wrong”. Also not interpretable, and not aligned across languages without explicit training.

F3 · Language models and RNNs

Increasing n from 3 to 6 makes generated text more coherent but the model worse. Explain.slide

Longer context captures more, but most 6-grams are never seen: counts hit zero (sparsity, worsened by n), the context itself is often unseen (no fallback), and storage grows. So you cannot simply raise n — that tension motivates neural LMs.

An n-gram model assigns probability 0 to a perfectly grammatical sentence. Name the cause and two fixes.slide

An n-gram in it never occurred in training (count 0). Fixes: smoothing (add a small count to every n-gram) and backoff (use a shorter context). If the context is unseen the ratio is undefined — backoff is then the fix.

A fixed-window neural LM removes sparsity. What problems remain?slide

The window is too small and can never be large enough; enlarging it enlarges the weights; and inputs at different positions are multiplied by different weights, so there is no symmetry or parameter sharing — the same word at position 2 and 3 is learned separately.

Give three advantages and two disadvantages of an RNN LM over a fixed-window model.slide

Advantages: any-length input; step t can use information from many steps back; model size does not grow with context; same weights every step. Disadvantages: sequential computation is slow; in practice it struggles to retrieve information from far back.

What is teacher forcing, and where does the training–test mismatch come from?slide

During training the model is fed the true previous word at each step regardless of what it predicted. At test time it must consume its own previous output, so an early error can compound — a mismatch teacher forcing hides.

A model reports perplexity 4.07 and another 1.44. Interpret.slide

Perplexity is exp(average cross-entropy): roughly the number of equally likely words the model is torn between. 1.44 ≈ very confident and mostly right; 4.07 ≈ nearly guessing among four. Lower is better; compare only on the same data and vocabulary.

Why is a bidirectional RNN suitable for sentiment classification but not for language modelling?slide

Sentiment sees the whole sentence — “not … good” needs both sides. A language model must predict the next word without seeing it, so a backward pass over future words would leak the answer.

Why is NER harder than POS tagging and how does BIO help?slide

NER must segment (find where an entity starts and ends — “United Airlines Holding”) and resolve type ambiguity; POS has one tag per word. BIO encodes spans as one label per token: B begins, I continues, O outside — turning NER into POS-style sequence labelling with 2n+1 tags.

Explain how an LSTM mitigates vanishing gradients.slide

The cell state is updated additively, c_t = f⊙c_{t−1} + i⊙c̃. If the forget gate is near 1 the cell is carried almost unchanged and gradient flows back along it without repeated squashing. A plain RNN has no such control and must hope its weights preserve information.

When would you choose a GRU over an LSTM?practice

When parameters, memory or speed matter: GRU has two gates, no separate cell, ~25% fewer parameters (3 vs 4 weight blocks). Accuracy is often similar; the LSTM's extra cell can help on very long dependencies.

Why does a seq2seq model without attention fail on long sentences, and how does attention repair it?slide

Everything about the source must be squeezed into one fixed-size vector — an information bottleneck. Attention lets each decoder step weight all encoder states, giving a dynamic context, a direct path to distant source words, and interpretable alignment.

In what sense is NMT a “conditional language model”?slide

The decoder is a language model (predicts the next target word) conditioned on the source sentence as well as the previous target words: P(y_t | y_<t, x).

Attention solved the bottleneck. What is still wrong with recurrent models?slide

Computation is sequential — step t needs t−1 — so it cannot be parallelised over time, which inhibits training on very large datasets; and long-range interaction still passes through many steps.

F4 · Coreference and question answering

A mention-pair model gives (I, my) = 0.98 and wrongly (my, she) = 0.7. What happens after the transitive closure?slide

I–my and my–she link, so closure forces I = she — a wrong merge of two clusters. One bad high score can merge an entire chain (“chain explosions”); one missed link splits a real cluster (“broken clusters”).

Classify: “Before she arrived, Anna phoned.” “John arrived late because he missed the bus.”slide

First: cataphora (she refers forward to Anna). Second: anaphora (he refers back to John).

Why does mention-ranking fix the clustering problem of mention-pair, and what is the dummy antecedent for?slide

Each mention chooses a single best antecedent, so one bad score affects one link, not a whole chain via closure; clusters follow from the chosen links. The dummy (“no antecedent”) option lets a first mention start a new cluster instead of being forced to link to something.

Name the four parts of the end-to-end span representation g_i and what each contributes.slide

[x*_START, x*_END, x̂_i, φ(i)]: BiLSTM states at the span's start and end (context left and right of the span); an attention-weighted head representation of the span's words (the span itself); and extra features such as span width (information not in the text).

Why is clustering-based coreference more robust than deciding each pair in isolation?slide

The merge score pools evidence from all cross pairs of two clusters — types agree, many pairs look compatible, context matches — so an ambiguous single pair (“Google” / “Google Plus”) is decided with more signals.

Describe the three stages of an IR-based factoid QA system and one thing each stage extracts or produces.slide

Question processing → answer type, query keywords, focus, relations. Passage retrieval → documents from the IR engine, segmented into passages and re-ranked using the answer type. Answer processing → a typed NER tagger extracts candidates which are ranked by features (type match, keyword distance, novelty …).

A system returns correct answers at rank 1 for 50 questions and rank 5 for 50. Accuracy@1 vs MRR?practice

Accuracy@1 = 50%. MRR = (50·1 + 50·0.2)/100 = 0.60. MRR credits the rank-5 hits; accuracy@1 ignores them.

Why can a dense bi-encoder retrieve “How do I cure a headache?” → “Ways to relieve head pain” where keyword search fails?practice

Question and passage are mapped into the same vector space trained contrastively so paraphrases land close even with no shared words. Passages are pre-encoded, so search is a fast similarity lookup.

F5 · Sentiment analysis

“Its battery is awesome but camera is very poor.” Why is sentence-level classification inadequate and what is the right task?slide

Any single label is wrong — the sentence is positive about one target and negative about another. Aspect-based sentiment analysis: extract aspect terms (battery, camera) and classify the sentiment toward each.

“The food is very cheap here” vs “The service is very cheap here.” What does this show about lexicons?slide

The same word flips polarity with its target and domain; a fixed lexicon assigns one polarity, so it cannot capture context-dependent sentiment. Also fails on word senses (“deadly”) and multi-word phrases.

“This movie is awesome to put you to sleep.” Which two sub-problems does it combine and why do lexicons fail?slide

Sarcasm (criticism disguised as praise) and implicit sentiment. “Awesome” is a positive lexicon word, so a lexicon scores it positive; the true sentiment is negative.

What is thwarting? Give an example.slide

A small portion of the text dictates the overall sentiment: “Impressive story, good acting, however, it didn't meet my expectation.” Positive words dominate by count but the final clause decides.

Why does a sentiment CNN max-pool over time?slide

Sentences vary in length but the classifier needs a fixed-size vector. Max over every filter keeps the strongest signal (e.g. the “very good” bigram) wherever it occurs, giving a fixed-length, position-invariant representation.

Order TD-LSTM, TC-LSTM, AT-LSTM, ATAE-LSTM by how they use the target, and say what each adds.slide

TD: left LSTM and right LSTM around the target. TC: + target vector concatenated to every word. AT: target embedding used in the attention layer, so attention picks the words relevant to it. ATAE: target embedding at both the input and the attention layer. A plain LSTM uses no target at all and cannot tell battery from camera.

For target “camera” in “Its battery is awesome but camera is poor”, which word should attention weight highest and why?slide

“poor” — attention conditioned on the aspect learns that opinion words near/related to “camera” matter; for “battery” it would highlight “awesome”.

A Hindi sentiment model hits many OOV words. Describe the deck's fix.slide

Learn bilingual word embeddings into a shared space (skip-gram with contexts from both languages on a parallel corpus). For an OOV word, translate to English and look up the English embedding (also absorbing spelling variants); add English lexicon features (Bing Liu, MPQA, SentiWordNet). Train on Hindi (multi-lingual) or on English and test on Hindi (cross-lingual).
